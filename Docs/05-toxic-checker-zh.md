# 页面设计：有毒食物和植物检测器

**URL**: `https://petsmetrics.com/shared/toxic-checker/`  
**模板**: A — 工具页面（带侧边栏的两列布局）  
**优先级**: P0 · 上线日 · **最高 SEO 流量价值**  
**适用对象**: 狗狗和猫咪（共享工具，物种切换）

---

## 1. 页面目标

整个网站的**主要 SEO 流量引擎**。必须排名：
- "狗狗能吃[食物]吗" — 数百个长尾变体
- "[植物]对猫咪有毒吗" — 猫咪特定变体
- "[食物]对宠物安全吗" — 共享变体

每个食物/植物条目也会生成自己的静态 SEO 落地页（例如 `/dog/can-dogs-eat-grapes/`）。

**用户意图**: 紧急即时查询（"我的狗狗刚吃了葡萄"）或好奇预防（"计划分享食物"）。**速度至关重要** — 结果必须在输入后 200ms 内出现。

## 6. 单个食物落地页

每个食物项都生成一个静态页面。示例结构：

**URL**: `/dog/can-dogs-eat-grapes/`

```
┌──────────────────────────────────────────────────────────────────┐
│  🔍  检查另一种食物或植物：                                      │
│  ┌──────────────────────────────────────────────┐  [检查 →]   │
│  │  例如，"巧克力"、"牛油果"、"百合"...         │              │
│  └──────────────────────────────────────────────┘              │
│  ← 返回有毒检测器                                               │
├──────────────────────────────────────────────────────────────────┤
│  狗狗能吃葡萄吗？              （H1 — 匹配搜索查询）            │
│  🔴 不 — 葡萄对狗狗有毒                                        │
│                                                                  │
│  [完整结果卡片 — 与主工具结果相同]                              │
│                                                                  │
│  常见问题               （FAQPage 架构）                        │
│  ─────────────────────────────────────────────────────────────   │
│  问: 如果狗狗吃了一个葡萄会怎样？                                │
│  答: 即使一个葡萄也可能导致肾脏损伤...                          │
│                                                                  │
│  问: 葡萄干和葡萄一样危险吗？                                    │
│  答: 是的 — 葡萄干甚至更浓缩...                               │
│                                                                  │
│  问: 狗狗葡萄中毒的症状是什么？                                  │
│  答: 呕吐、嗜睡、食欲下降...                                   │
│                                                                  │
│  [检查另一种食物 →]              （链接回工具页面）              │
│  [查看更多对狗狗有毒的食物 →]                                    │
└──────────────────────────────────────────────────────────────────┘
```

> **内部链接策略**: 每个食物落地页在顶部嵌入一个实时搜索框，将用户链接回工具页面。工具页面结果卡片向前链接到详细的食物落地页。这种双向内部链接结构增强了两种页面类型的 SEO 权威性，并通过在每个页面上为用户提供明确的"下一步操作"来降低跳出率。

这些页面是**最高优先级的 SEO 资产** — 在构建时静态生成，每个食物 × 每个物种一个页面。目标: 上线时 400+ 个唯一落地页。

## 8. 移动端布局

- 搜索栏: 全宽，52px 高度，顶部附近粘滞
- 物种切换: 2 个大点击目标，全宽
- 结果卡片: 全宽，无边栏
- 紧急联系: 永久粘滞栏，带有点击拨打的电话号码
- 类别浏览: 水平滚动，换行标签
- 侧边栏在移动端移到主内容下方

**移动端紧急 UX 优先级**: 电话号码必须是 `<a href="tel:">` 链接，用于一键拨打。

## 9. 性能说明

- JSON 数据库在单个请求中加载，缓存到 localStorage 中 24 小时
- Fuse.js 搜索库: gzip 后 < 10KB
- 结果显示中无图片（纯 CSS 状态系统）
- 单个落地页: 完全静态 HTML，无需 JS
